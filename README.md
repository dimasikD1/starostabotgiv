# Староста Бот

**Староста Бот** — Telegram-бот с Mini App для организации учебной жизни студентов, старост и администрации учебных заведений.

Проект объединяет расписание, работу с учебными группами, посещаемость, домашние задания и объявления в одном интерфейсе.

- **Telegram-бот:** [@starostagivbot](https://t.me/starostagivbot)
- **Канал обновлений:** [@starostabotgiv](https://t.me/starostabotgiv)

## История проекта

«Староста Бот» — самостоятельный образовательный стартап, который начал развивать обычный выпускник среднего профессионального образования Краснодарского кооперативного института (ККИ РУК), направления ИСП.

Идея проекта выросла из реальных задач студенческой жизни: упростить работу старост, сделать учебную информацию доступнее и собрать расписание, посещаемость, домашние задания и объявления в одном месте.

Проект развивается постепенно — от решения задач своей учебной среды к идее единой платформы, которой смогут пользоваться разные колледжи и университеты. Это независимая инициатива, создаваемая небольшими шагами, с опорой на обратную связь студентов и старост.

## Возможности

### Для студентов
- Просмотр расписания на сегодня, завтра и неделю.
- Просмотр информации о своей учебной группе.
- Доступ к домашним заданиям и объявлениям.
- Работа с Mini App внутри Telegram.

### Для старост и заместителей
- Управление студентами своей учебной группы.
- Работа с посещаемостью по отдельным занятиям.
- Опросы и взаимодействие с участниками группы.
- Публикация и просмотр учебной информации.

### Для администраторов и владельцев
- Управление учебными группами и пользователями.
- Назначение старост и заместителей.
- Регистрация учебных заведений.
- Назначение администраторов учебных заведений.
- Разделение данных и доступа по учебным заведениям.

## Mini App

Mini App адаптирован для открытия из Telegram и включает основные разделы студенческого кабинета и инструменты управления. Интерфейс рассчитан в том числе на мобильный Telegram WebView.

- Мгновенный показ последних сохранённых данных при открытии и при временной недоступности сервера.
- Подсказка «Сейчас идёт пара» с обратным отсчётом до конца занятия.
- Расписание на сегодня, завтра и неделю, посещаемость по парам, домашние задания с фото и видео.
- Объявления и отчёты в HTML.
- Кнопка обновления данных и автоматическое обновление при возврате в приложение.

## Поддерживаемые учебные заведения

Проект развивается в сторону единой платформы для нескольких колледжей и университетов: каждое учебное заведение получает собственные группы и административные права.

Текущая структура данных предусматривает привязку групп к учебному заведению. Развитие иерархии факультетов, направлений и курсов продолжается.

## Миграция на TypeScript

Работа продолжается в отдельной ветке `typescript-migration`; production-ветка `main` и развёртывание Amvera не меняются автоматически. В домене регистрации вынесена обработка выбора группы и совместимость со старыми профилями, включая записи, где вместо названия группы сохранён её ключ. Проверки добавляются до дальнейшего переноса обработчиков. Отбор занятий на выбранную дату и сортировка по времени начала вынесены в типизированный модуль расписания с отдельными тестами.

Проект рассчитан на запуск в Amvera из GitHub-репозитория.

1. Подключите репозиторий к приложению Amvera.
2. Укажите необходимые переменные окружения.
3. Запустите сборку и проверьте логи приложения.
4. Для автоматического запуска обновлений после отправки изменений в GitHub настройте GitHub Webhook в настройках репозитория и приложения Amvera.

### Переменные окружения

Обязательная переменная:

- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.

Дополнительные параметры:

- `WEBAPP_URL` — публичный HTTPS-адрес Mini App для кнопки «Открыть кабинет».
- `TIME_ZONE` — часовой пояс расписания и посещаемости, по умолчанию `Europe/Moscow`.
- `DATA_DIR` — каталог данных, по умолчанию `/data`.
- `OWNER_TELEGRAM_ID` — числовой Telegram ID владельца.
- `DB_BACKUP_INTERVAL_MS` — как часто обновлять резервную копию базы, по умолчанию раз в 60 секунд.

Параметры расписания:

- `SCHEDULE_SITE_URL`
- `SCHEDULE_API_URL`
- `SCHEDULE_DAYS`
- `SCHEDULE_TIMEOUT`
- `SCHEDULE_BRANCH`, `SCHEDULE_KIT`
- `SCHEDULE_BRANCH_ID`, `SCHEDULE_GROUP_ID`

Фактический набор переменных зависит от конфигурации приложения. Не публикуйте токены, пароли, webhook secrets и другие секреты в репозитории.

### Проверка работоспособности

Сервер отдаёт `GET /healthz` с версией и временем работы. Ответ `200` и `{"ok":true}` означает, что процесс запущен. Для проверки сборки и тестов:

```bash
npm run check
npm test
```

## Данные

Работа с данными пользователей и учебных групп зависит от настроенного хранилища приложения. В текущей конфигурации используется каталог данных `/data`. Убедитесь, что для него настроено постоянное хранение на хостинге.

## Важные замечания

- Расписание зависит от доступности источника расписания учебного заведения.
- При сбоях внешнего источника приложение должно по возможности сохранять и показывать ранее загруженные данные.
- Распознавание списков студентов по фотографии (OCR) сейчас отключено.
- В проекте нет пользовательского интерфейса подписки.

Пагинация отметок посещаемости по отдельной паре теперь также собрана в типизированном модуле: обработчик использует общий helper для страницы, статусов и кнопок перехода.

Выбор пары для отметок посещаемости перенесён в `attendance-lesson-choices.ts`: сохранены подписи, нумерация, обрезка названия и callback-индексы; тесты проверяют прежнее поведение.

## Статус миграции на TypeScript

Работа ведётся в отдельной ветке `typescript-migration`. Production-ветка `main` и приложение Amvera не переключаются автоматически.

**Последний выполненный этап:** разбор номера учебной группы для команд `/starosta`, `/zam` и `/setstarosta` перенесён в типизированный модуль `role-command-input.ts` с тестами. Также в TypeScript перенесена политика доступа для `/starosta`, `/zam`, `/setstarosta` и `/setstudent`: сохранено различие между правами владельца платформы и администратора Telegram-группы, включая прежнее поведение для каждой команды. Подготовка списка чатов для команды `/announce` также перенесена в типизированный модуль: сохраняются числовые ID, устранение дубликатов и прежний порядок выбора. Формирование данных отчёта `/pollreport` перенесено в TypeScript: подсчёт ответов, числа не ответивших и отображаемые имена теперь проверяются отдельными тестами; форматирование Telegram-сообщения и права доступа остались без изменений. Разбор callback-данных карточек, редактирования контактов и пагинации списка студентов перенесён в `parseStudentRosterAction()` модуля `student-management.ts`; некорректные индексы и неизвестные типы действий отклоняются. Подтверждение текстового импорта списка студентов также перенесено в типизированный persistence-workflow: замена списка, очистка временных данных импорта и сохранение базы выполняются одним проверяемым этапом; сохранены лимит в 100 студентов и данные посещаемости. Отмена импорта списка студентов также использует отдельный типизированный workflow: он удаляет только временные поля импорта, не затрагивая профиль пользователя и другие незавершённые действия, и сохраняет состояние базы. Формирование HTML-предпросмотра списка студентов перед подтверждением перенесено в `formatStudentImportPreview()` модуля `student-import.ts`; названия группы и ФИО экранируются перед отправкой в Telegram; форматтер поддерживает обычный и нумерованный предпросмотр для личного чата и группового импорта. Извлечение аргумента `/setgroup` перенесено в типизированную функцию `parseSetScheduleGroupArgument()`: сохраняются названия групп с пробелами и поддерживается обращение к команде с `@username` бота. Проверка точного совпадения с настроенными группами остаётся в `resolveScheduleGroupName()`. Разбор аргумента команды `/group` перенесён в типизированную функцию `parseStudyGroupSelection()`: она принимает только номер одной из настроенных групп или её точное название и сохраняет прежние варианты ввода. Проверка и нормализация текста при изменении username и телефона студента перенесена в `parseStudentContactInput()` на TypeScript; сохранены прежние правила формата, очистка через прочерк и тексты ошибок. Формирование карточки студента для кнопок списка `/students` перенесено в TypeScript: сохраняются прежние подписи, резервные значения для пустых контактов и экранирование Telegram HTML; обработчики кнопок и изменение контактов не менялись. Разбор аргумента имени для `/student` перенесён в типизированную функцию: поддерживаются команды с обычным именем бота и с `@username`, лишние пробелы нормализуются; добавление студента и его сохранение остались в прежнем workflow. Проверка аргументов `/linkgroup` и `/unlinkgroup` перенесена в TypeScript: проверяются номера учебных групп, а для привязки — наличие ID курса; тексты ошибок и сохранение структуры остаются прежними. Формирование заголовка списка `/students` теперь выполняется в TypeScript с экранированием названия группы для Telegram HTML; проверка покрывает спецсимволы и некорректное число студентов. Клавиатура, карточки и пагинация не менялись. Разбор номера студента для `/delstudent` также перенесён в типизированную функцию с проверкой целочисленного диапазона; фактическое удаление и сохранение базы по-прежнему выполняются через существующий workflow. Формирование заголовка списка `/students` перенесено в TypeScript с безопасным экранированием названия группы для Telegram HTML; клавиатура, карточки и пагинация остаются совместимыми с текущим интерфейсом. Логика формирования списка `/allroles` также перенесена в TypeScript: модуль учитывает учебную группу и привязанные Telegram-чаты, исключает владельцев платформы и сохраняет назначенных старост/заместителей даже при отсутствии профиля. Форматирование Telegram-сообщений осталось в `index.mjs`. Предыдущие этапы перенесли политики `/registerchat` и `/openchat`.

Разбор аргументов owner-only команд `/grant`, `/revoke` и `/subinfo` вынесен в типизированный модуль `admin-command-input.ts`. Сохранены допустимые сроки выдачи, варианты бессрочного доступа и поддержка Telegram bot mention; проверки владельца и личного чата, изменение данных подписки, история операций и уведомления остаются в прежних обработчиках.

Формирование отчёта владельца `/stats` перенесено в `owner-stats.ts`: подсчёт пользователей, ролей, групп, старых записей подписок и пожертвований теперь покрыт отдельными тестами. Список ID владельцев передаётся явно, поэтому их бесплатный доступ не попадает в статистику подписок. Доступ к команде, личный чат и HTML-ответ Telegram остались в существующем обработчике; пользовательский интерфейс подписки не добавлялся.

Формирование ответа `/groups` перенесено в `attached-groups.ts`: сохранены порядок групп, нумерация и прежнее сообщение для пустого списка. Ограничение личного чата и получение данных из текущей базы остались в обработчике Telegram. Разбор числового Telegram ID в командах `/delrole` и `/removerole` перенесён в отдельный типизированный парсер; проверка владельца, изменение ролей и сохранение базы остались в прежнем обработчике. Разбор аргумента `/role` и `/roles` перенесён в `parseRoleViewAction()` модуля `role-view-command-input.ts`: типизированный результат различает просмотр назначений, добровольный переход в роль студента и неизвестную команду. Снятие ролей и сохранение данных остаются в прежнем обработчике. Разбор аргументов ручной отметки `/mark` перенесён в `parseManualAttendanceMarkInput()` модуля `attendance-core.ts`: номер студента и статус `present`/`absent` проверяются типизированно, а проверка фактического наличия студента, выбор активной пары и запись посещаемости остаются в прежнем обработчике. Извлечение ID учебного заведения из `/structure` также вынесено в типизированный парсер; проверка доступа и формирование подробного отчёта о структуре остались в Telegram-обработчике.

Политика команд `/attach` и `/detach` перенесена в `group-attachment-command.ts` и покрыта тестами: сохранены ограничения по типу Telegram-чата, проверка администратора и прежнее поведение `/detach` вне групп (команда игнорируется). Регистрация/удаление записи группы, сохранение базы и отправка сообщений остались в существующих обработчиках.

**Оценка оставшейся работы:** около 2–3 крупных этапов:
1. Перенести оставшиеся административные операции и обработчики команд/кнопок.
2. Завершить регистрацию, middleware, оставшиеся проверки доступа, фоновые задачи, уведомления и публикацию расписания.
3. Завершить TypeScript entrypoint, полную сборку и проверку совместимости с Amvera.

Это ориентировочная оценка по функциональным блокам, а не процент готовности. Список обновляется после завершённых этапов. Миграция считается завершённой только после прохождения CI и проверки запуска; production переключается только по отдельному подтверждению.

## TypeScript migration

The Telegram group-verification flow now gets its member permission policy from the typed
`buildVerifiedMemberChatPermissions()` function in `bot-amvera/domain/chat-permissions.ts`.
The Telegram API call and verification workflow remain in the existing bot entrypoint.

Дополнительно выбор самого свежего автоматического опроса для `/pollreport` вынесен в типизированную функцию `findLatestAttendancePollRecord()`: сохраняются фильтрация по ID Telegram-группы и прежняя сортировка по дате и времени; добавлены тесты выбора группы и последнего опроса.

Разбор аргументов команд назначения и снятия администратора учебного заведения (`/setinstadmin` и `/removeinstadmin`) вынесен в `parseInstitutionAdminCommandInput()` модуля `admin-command-input.ts`. Сохранены обработка упоминания бота, порядок аргументов и прежние проверки существования заведения и числового Telegram ID.

Разбор полей `/addinstitution`, а также извлечение ID для `/deleteinstitution` и `/instadmins` перенесены в `admin-command-input.ts`. Сохранены разделитель `|`, поддержка упоминания бота, прежние ограничения длины названия/сокращения/города и тексты проверок в Telegram-обработчиках.

Формирование HTML-отчёта команды `/structure` перенесено в `formatInstitutionStructureMessage()` модуля `institution-structure.ts`. Сохранены порядок факультетов, направлений, курсов и групп, подсказка для пустой структуры, HTML-экранирование и ограничение Telegram-сообщения в 3900 символов; проверка доступа и отправка ответа остались в Telegram-обработчике.

Повторные запросы Telegram API при запуске вынесены в типизированный `executeWithRetry()` (`domain/startup-retry.ts`). Сохранены пять попыток по умолчанию, экспоненциальные задержки 1,5/3/6/10 секунд, прежние сообщения журнала и итоговая ошибка; ожидание и логирование передаются через зависимости для изолированного тестирования.

Переходы статусов бота в Telegram-группах классифицируются типизированной функцией `classifyGroupBotMembershipTransition()` в `domain/group-bot-membership.ts`. Она отделяет вступление, повышение/снятие админ-прав и необходимость проверки разрешений от Telegram side effects; регистрация чата и уведомления остались в обработчике.


Логика подготовки выбора учебной группы перенесена в типизированную функцию `resolveStudyGroupRegistration()`: она проверяет ключ настроенной группы, находит связанную группу учебного заведения, сохраняет совместимые поля профиля и определяет, требуется ли завершить проверку участника. Вызовы Telegram API, снятие ограничений и запись базы остаются в обработчике, чтобы не менять порядок внешних операций.


Фоновые задачи Telegram получили общий типизированный механизм блокировки от параллельного запуска. Отдельные блокировки используются для автоматических опросов посещаемости, еженедельной публикации расписания и мониторинга изменений расписания. Блокировка освобождается в `finally`, в том числе при ошибке; независимые задачи не мешают друг другу. Telegram API и сохранение состояния остались в orchestration-коде.


Формирование текста автоматических напоминаний о занятиях и вопросов опроса посещаемости выделено в типизированные функции расписания. Сохранены прежние формулировки, HTML-экранирование темы и аудитории; отправка сообщений и создание Telegram-опросов остаются в runtime-обработчике.


Логика маршрутизации сообщений в процессе импорта списка студентов вынесена в типизированный `domain/student-import-workflow.ts`. Она определяет, относится ли фото к активному импорту, а также различает текстовый импорт в личном чате, ответ в исходной группе, пустое сообщение, отмену и команду. Проверка прав, разбор ФИО, Telegram-ответы и сохранение данных остаются в обработчиках; распознавание фото/OCR не включается.

### Миграция фоновых задач посещаемости

Оркестрация автоматических напоминаний за 30 минут и опросов посещаемости за 10 минут перенесена в типизированный модуль `bot-amvera/schedule/attendance-jobs.ts`. Модуль управляет непересекающимися циклами, перебирает чаты, загружает расписание, формирует задачи, сохраняет маркеры отправки и продолжает обработку следующих групп при ошибке источника. Telegram API, база данных и формат времени передаются через зависимости из `index.mjs`; тексты уведомлений и временные окна не менялись. OCR, подписка и пользовательский интерфейс не затрагивались.

Проверки включают сценарии напоминания, сохранения результата опроса, отсутствия повторной отправки, ошибки одного источника и блокировки параллельного цикла.

Доступ к команде, выбор последнего опроса и подготовка статистики остаются в прежнем обработчике.
